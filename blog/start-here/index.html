Answers. What this series claims, and how to read it.

Why

  • Tests run the program on selected inputs. Code review reads the source. Neither states what the program must preserve on every execution.
  • This series writes that requirement as a spec and checks it with a proof. The proof checks executions that no test runs.

Thesis

  • A model states the requirement in a form that Rocq can check. A refinement links the model to the code. All seven posts use one program, ByteStore.

Coverage and scope

  • Will. The series verifies one C++17 program from source. The program comes with its spec and its tests. Each claim carries one label: proved, tested, or trusted.
  • Scope. The series covers one property family in one program. It makes no general claim about verified C++.

Who

  • The series is for C++ and security engineers. Post 02 explains how to read the Rocq code.

Run it

  • Post 01, section 5 gives the full repro. Everything is pinned at commit. See the repro guide.

Status. Research in progress.
